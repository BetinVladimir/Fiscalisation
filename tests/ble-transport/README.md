# Actual BLE transport interop without an external UI checkout

`make iot-cbor-encoder-interop-test` uses this private test-only package; neither application is installed. It requires exact Node22.14.0/npm10.9.2, Go, a C++17 host compiler, SQLite3 headers/library and real firmware cJSON/mbedTLS sources. It runs the actual native issuer/queue/processor/storage/result/publisher producer, an independent Go decoder, the real MiniPOS result waiter and both actual browser BLE classes. SDK boundaries are fake; auth/codec/transport implementations are not stubbed. Full UI/export, native devices and BLE HIL remain separate gates.

Six exact direct versions and all109 registry lock entries are copied from actual application lockfiles, preserving resolved URLs/integrities and optional platform packages. `check_lock.py` verifies every origin, exact app-lock hashes, app direct pins, closed required/optional dependency graph and no file/UI dependencies. No unlocked registry resolution occurs. To propose a dependency refresh, run `python3 tests/ble-transport/derive_lock.py --output /tmp/transport-lock-candidate`, then review all package/lock/origin changes before replacing files. Changes to either app lock intentionally require review, even when UI-only.

The runner verifies tool versions before install, then creates a new temporary directory with no node_modules/cache, empty npm user/global config and unchanged HOME. It clears ambient npm config and NODE_OPTIONS/NODE_PATH loader settings; it does not reject those environment variables. `npm ci --ignore-scripts` installs only locked packages into this directory; no installed/global dependency tree is copied. All optional platform packages stay in lock and matching binaries are installed by npm. Installed hidden-lock entries must match reviewed version/resolved/integrity metadata. Source copies preserve the exact original eleven runtime/test files and verify original+copy SHA before/after tests; symlink escapes fail. Import graph additions require explicit review and fail naturally if missing.

Set `CJSON_SOURCE_DIR` (or the existing native runner's CJSON_SOURCE directory), `MBEDTLS_SOURCE_DIR`, optional `MBEDTLS_CRYPTO_LIBRARY`, `CC`, `CXX`, `GO`, `NODE`, `NPM`, and optional isolated Go caches. NPM/NODE/GO accept shell-split command prefixes, allowing a temporary npm10.9.2 CLI without any global installation. Official Node22.14.0 bundles npm10.9.2: [upstream npm metadata](https://raw.githubusercontent.com/nodejs/node/v22.14.0/deps/npm/package.json). Native producer has bounded300s outer timeout; install300s, other subprocesses180s and existing per-process native deadlines remain active. GitHub job timeout is an additional outer bound.

Twelve producer rows and BFF1 fragments must validate before client tests. The Node waiter test must pass without skips; the full browser lifecycle file must pass at least66 tests with both named fixture-fed projection tests passed and no pending tests. A zero-exit skipped test run is rejected. Negative/full-width amounts are synthetic representation vectors, not valid monetary-operation claims. Exact state aliases, financial durable behavior and BLE origin ownership remain unchanged.

`BLE_TRANSPORT_EVIDENCE_DIR` selects a durable local diagnostic directory (otherwise a temporary evidence directory is printed). Local raw producer/npm logs and public synthetic fixtures may be useful for private diagnosis but are **not approved bulk-upload artifacts**: future producer logs can include private issuer details. Workflow upload is an explicit safe allowlist: `manifest.json`, `vitest.json`, `dependency-summary.json` only. Manifest records hashes/counts/versions, never fixture rows, raw native output or npm command arguments. Do not add the entire directory to upload. These files are software evidence, not device/certification proof.

`python3 -m unittest discover -s tests/ble-transport -p 'test_*.py' -v` covers lock/integrity/UI dependency rejection, source mutation/removal/symlinks, invalid fixture frames/counts, and skipped/reduced report rejection. Existing S3 CI uses pinned setup-node and the same exact official SDK source environment as firmware/native regressions. App manifests/locks, selected TS graph/tests, dependency package, backend producer and firmware changes are in workflow filters. Full Linux/GitHub execution remains required after review; a local macOS clean run does not prove it.
