# SUPTO N-18 end-to-end compliance gate

Набор связывает русскую каноническую редакцию Н-18, Приложение № 29, машинную трассировку требований и действующий MiniPOS/Fiscalisation full-stack journey.

## Запуск

Из корня репозитория:

```sh
./tests/e2e/supto-n18/run.sh
```

Быстрая проверка нормативной трассировки и контрактов без Docker:

```sh
SUPTO_CONTRACT_ONLY=1 ./tests/e2e/supto-n18/run.sh
```

Строгий certification gate (ожидаемо завершится ошибкой, пока остаются внешние/HIL-пробелы):

```sh
STRICT_SUPTO_CERTIFICATION=1 ./tests/e2e/supto-n18/run.sh
```

## Что контролируется

- наличие всех пунктов 1–23 Приложения № 29 и непрерывность канонического документа Н-18;
- отдельная disposition-запись для каждого `SUPTO-29-01`…`SUPTO-29-24`, владелец, инварианты и существующие evidence-файлы;
- API для атомарного открытия продажи с первой строкой и УНП, частичной/полной отмены, сторно, синхронизации времени, сессии рабочего места, аудита и экспортов;
- настоящий изолированный full-stack путь: email OTP, onboarding компании, Fiscal enrollment, ACTIVE binding, синхронизация торгового объекта/кассы/оператора, CASH и CARD, чек, сторно, idempotency и протокол локального устройства (`readyz` → `intents` → `operations`);
- browser journey для split payment и единственной агрегатной фискализации;
- запрет ложного статуса «полное соответствие», пока в trace остаются `PARTIAL`, `EXTERNAL_BLOCKED` или `production_blocked`.

## Граница доказательства

Software E2E не заменяет сертификацию НАП и проверку реального оборудования. Текущие незакрытые пункты автоматически перечисляет `certification-gate.mjs`; типичные внешние доказательства — HIL с физическим ФУ, доверенный источник времени, production IdP/архив/retention, подписанные артефакты сборки и экспертная приемка болгарского UI/форматов экспорта. Подмена этих доказательств mock-ответами запрещена.
