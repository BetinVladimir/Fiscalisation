# MVP completion audit

Дата среза: 2026-08-09. Статус цели: **IN PROGRESS / PROD NO-GO**.

Этот документ не подменяет canonical roadmap. Он связывает фактическую реализацию в данном репозитории с критериями этапов 20–25 и запрещает считать simulator evidence доказательством hardware/legal readiness.

Полное соответствие этапам 1–25 дополнительно зафиксировано в `contracts/roadmap-stage-acceptance.json` и проверяется `make roadmap-acceptance-test`. Реестр требует существования каждого evidence artifact и Make target, запрещает gap у `SOFTWARE_PASS`, требует явный gap у внешних стадий и сохраняет Stage 25 в `PENDING_EXTERNAL_ACCEPTANCE`, пока acceptance record не подписан реальными approvers.

Stage 1 дополнительно проверяется `make governance-test`: два независимых product/database/Compose/Caddy ownership boundary, десять обязательных module owner roles, единая identifier policy и 14 P0 decision records. Внешний P0 не может пройти gate без существующего evidence artifact и `production_blocked=true`.

## Решение текущего среза

- Software regression: **PASS**.
- Stage 24 repeatability: **PASS для текущего software slice** — два последовательных `make full-regression` на неизменённом состоянии завершились с exit 0, включая Ed25519 evidence/tamper gate и two-Compose E2E.
- Base functional software MVP: **PASS для simulator/STUB/unsupported capability profile**; выбранные external hardware/payment tracks остаются deployment gates и не повышаются simulator evidence.
- Stage 25 handover artifacts: **READY FOR HUMAN SIGNATURE** — versioned machine-readable acceptance record, release notes, operations/backup runbook, rollback plan and support/escalation guide are present and checked by `make handover-test`. The gate requires all Product/Engineering/QA/Security/Compliance signatures to remain `PENDING_EXTERNAL_SIGNATURE` until supplied by real approvers.
- Pilot: **NO-GO** без выбранного hardware track и HIL evidence.
- Production Bulgaria: **NO-GO** без vendor/legal/НАП/БИМ evidence, внешнего IdP deployment evidence и подписанного release pack. Runtime RLS software enforcement уже PASS и не считается оставшимся blocker.

Текущий software evidence: unified regression после cashier least-privilege increment, 2026-08-09, exit 0; 92 OpenAPI operations, 32 UI cases, 39 security cases и 25 BG trace rows. CASHIER больше не читает employee directory/tenant-wide report, а order list требует active app-bound identity и исключает чужой employee order ID. Increment подтверждён полным PostgreSQL/RLS, platform-build и two-Compose/Caddy прогоном. Это не повышает simulator/STUB до hardware, vendor, acquirer или legal PASS.
