# MiniPOS Web working-language review

Date: 2026-10-01. Status: **structurally complete, linguistic review open**.

The 42 working UI keys are present and non-empty in all 25 EU/RU locales. Eighteen established POS terms come from the checked-in BeeMiniPOS dictionary. Twenty-four MiniPOS Web-specific strings were generated by the local Ollama `qwen3.5:9b-mlx` model; EN/BG/RU overrides are maintained in `scripts/sync-work-translations.mjs`. `src/ui/workExtras.generated.json` stores the model output and `npm run translations:sync-work` reproduces the standalone web dictionary. No runtime fallback to English is used for these keys.

`tests/workTranslations.test.ts` validates the 25×42 structure. `e2e/work-language.spec.ts` switches through all 25 languages on a 360 px working screen, verifies navigation/sale labels and no horizontal overflow, then checks the management forms in EN/BG/RU/DE/FR. The long Slovak menu label initially caused horizontal overflow; the shared Paper selector now has a bounded width and wraps. Both E2E tests pass.

This does **not** certify semantic accuracy. Spot review found likely mistranslations in inherited Irish and Maltese POS terms and in new model output. For example, Irish `checkoutFiscal` was generated as `Óstáil agus fisiciúil`; neither this nor the alternate local model's `Íocaíocht agus fiosrú` reliably describes issuing a fiscal receipt. Inherited Irish `sales` and `quantity` also look suspect. Financial actions, offline reconciliation warnings, shift terminology, and accessibility labels require bilingual editorial review in every locale before release. The UI-optimization translation gate remains open. Technical API error strings and diagnostic JSON also need a localized presentation strategy.
