# MVP implementation status

## Implemented

- Fiscal public HTTP vertical: versioning, idempotency, sale, first-line УНП, EUR/tax validation, cash/card, reversal, readiness, shifts, cash movement, X/Z/KLEN/FM report operations, connectivity, BLE session resource and edge sync ACK.
- Fiscal polling surface includes tenant-filtered operation listing, sale cancellation, normalized receipt retrieval and explicit UNKNOWN→RECONCILING transition.
- Fiscal administrative surface now persists tenant-isolated organizations, locations, registers, operators and devices with UUIDs, optimistic versions, uniqueness/reference validation, device bindings, capability manifests, provisioning sessions and redacted diagnostics.
- Device activation now fails closed from creation onward: every new device must start in `DRAFT`, cannot skip `PENDING_SERVICE_ACTIVATION`, only ACTIVE devices may bind to an ACTIVE register, ACTIVE devices cannot request a bootstrap provisioning session, and an ACTIVE PROD device requires both approved-type and service-contract evidence references. These controls validate evidence presence without claiming the external evidence is genuine.
- Created provisioning sessions are now durable tenant-bound resources, survive repository and real PostgreSQL typed-only restart and participate in the normal audit/persistence path. The storage-mode-2 integration test proves their exact payload/tenant/state projection and reconstruction. Cross-tenant reads fail closed; non-provisionable device state returns explicit HTTP 409 `DEVICE_NOT_PROVISIONABLE`, while an absent/foreign device remains 404.
- Shifts are tenant-scoped and support list/get/open/close. Reports have persistent immutable JSON artifacts and list/get/download endpoints; resource and fiscal mutations append a persistent hash-chained audit ledger exposed read-only.
- Compliance exports persist real tenant-filtered JSON, CSV or minimal standards-compliant XLSX artifacts with SHA-256 manifests; invalid periods/types/formats and cross-tenant reads are rejected.
- Public API enforces the OpenAPI 16–255 character idempotency-key constraint; receipts include operation, total, issue time and immutable artifact identifiers.
- Effective-dated BG policy endpoints (`/country-policy`, `/tax-groups?effective_at=`) now expose the EUR policy and reject dates without an active policy. Sale lines are checked against the reviewed policy catalog; only the evidenced MVP B/20.00 seed is executable, while unreviewed A/C–H mappings fail closed pending a signed policy update.
- Fiscal list surfaces now implement the contract cursor/limit bounds with opaque cursors and `PageMeta`; operations support state/register filters, reports support register filtering, and audit events support actor/УНП/period filtering with strict RFC3339 period validation.
- Deterministic non-production simulator with hard PROD configuration guard.
- MiniPOS autonomous domain/API: employees/products with optimistic updates, shifts, orders, lines, checkout and reports; Fiscal is accessed only through its public HTTP API.
- MiniPOS now persists and exposes its autonomous single-location/single-workstation configuration with optimistic versioning. BeeMiniPOS edits location name/address, workstation name and the bound Fiscal register through the MiniPOS public API; changing the binding invalidates the active local BLE session in the UI.
- Fiscal and autonomous MiniPOS now persist every repository collection entry as an independent PostgreSQL JSONB row in one serializable transaction, each with its own authoritative generation marker and automatic one-time migration from the former aggregate snapshot. Empty authoritative state cannot resurrect legacy data; sales/orders, outbox/inbox, idempotency and sequence state survive restart in their isolated databases.
- Edge authority lease/fencing allocation, durable hash-chained SQLite WAL journal, three-month ACK-gated GC, encrypted directional BLE sessions and durable-before-device runtime.
- Edge sync now builds the full OpenAPI batch from unacknowledged SQLite events (maximum 100): normalized device events, contiguous journal sequence, previous committed hash, per-event chain, batch SHA-256 and HMAC signature. Fiscal accepts JSON and CBOR, verifies every layer before durable commit, and returns the complete signed acknowledgement with committed event hash, operation results and rejected array. Before the first network side effect, the uploader persists the exact pending first/last sequence and batch SHA-256 in SQLite. Ambiguous response loss, newly appended events and process restart therefore resend the identical idempotency key/body instead of expanding the batch and duplicating a backend commit. A valid bound ACK atomically advances cursor, acknowledges journal rows and clears the pending marker. A shared deterministic golden vector proves Edge builder/Fiscal verifier compatibility.
- An executable accelerated soak gate models all 864 five-minute slots across 72 hours of clean outages/ambiguous-after-commit losses and all 1008 ten-minute slots across seven journal days. It reopens SQLite daily, verifies zero lost events and duplicate backend commits, exact ACK replay, final cursor/hash, chain integrity, three-month ACK-gated retention, purge anchor continuity and produces a machine-readable Go JSON report. This is software time-model evidence only and does not promote physical SD/HIL endurance.

A terminal device result atomically materializes the tenant sale, operation, normalized receipt artifact and webhook/audit outbox event; malformed currency, totals, operator, tax, payment or tenant/device bindings fail closed. Same-batch acceptance/completion and split-batch correlation are idempotent.
