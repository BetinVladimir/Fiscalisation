# MVP implementation status

## Implemented

- Fiscal public HTTP vertical: versioning, idempotency, sale, first-line УНП, EUR/tax validation, cash/card, reversal, readiness, shifts, cash movement, X/Z/KLEN/FM report operations, connectivity, BLE session resource and edge sync ACK.
- Fiscal polling surface includes tenant-filtered operation listing, sale cancellation, normalized receipt retrieval and explicit UNKNOWN→RECONCILING transition.
- Fiscal administrative surface now persists tenant-isolated organizations, locations, registers, operators and devices with UUIDs, optimistic versions, uniqueness/reference validation, device bindings, capability manifests, provisioning sessions and redacted diagnostics.
- Shifts are tenant-scoped and support list/get/open/close. Reports have persistent immutable JSON artifacts and list/get/download endpoints; resource and fiscal mutations append a persistent hash-chained audit ledger exposed read-only.
- Compliance exports persist real tenant-filtered JSON, CSV or minimal standards-compliant XLSX artifacts with SHA-256 manifests; invalid periods/types/formats and cross-tenant reads are rejected.
- Public API enforces the OpenAPI 16–255 character idempotency-key constraint; receipts include operation, total, issue time and immutable artifact identifiers.
- Effective-dated BG policy endpoints (`/country-policy`, `/tax-groups?effective_at=`) now expose the EUR policy and reject dates without an active policy. Sale lines are checked against the reviewed policy catalog; only the evidenced MVP B/20.00 seed is executable, while unreviewed A/C–H mappings fail closed pending a signed policy update.
- Fiscal list surfaces now implement the contract cursor/limit bounds with opaque cursors and `PageMeta`; operations support state/register filters, reports support register filtering, and audit events support actor/УНП/period filtering with strict RFC3339 period validation.
- Deterministic non-production simulator with hard PROD configuration guard.
- MiniPOS autonomous domain/API: employees/products with optimistic updates, shifts, orders, lines, checkout and reports; Fiscal is accessed only through its public HTTP API.
- MiniPOS now persists and exposes its autonomous single-location/single-workstation configuration with optimistic versioning. BeeMiniPOS edits location name/address, workstation name and the bound Fiscal register through the MiniPOS public API; changing the binding invalidates the active local BLE session in the UI.
- Fiscal and autonomous MiniPOS now persist every repository collection entry as an independent PostgreSQL JSONB row in one serializable transaction, each with its own authoritative generation marker and automatic one-time migration from the former aggregate snapshot. Empty authoritative state cannot resurrect legacy data; sales/orders, outbox/inbox, idempotency and sequence state survive restart in their isolated databases.
- Edge authority lease/fencing allocation, durable hash-chained SQLite WAL journal, three-month ACK-gated GC, encrypted directional BLE sessions and durable-before-device runtime.
- Edge sync now builds the full OpenAPI batch from unacknowledged SQLite events (maximum 100): normalized device events, contiguous journal sequence, previous committed hash, per-event chain, batch SHA-256 and HMAC signature. Fiscal accepts JSON and CBOR, verifies every layer before durable commit, and returns the complete signed acknowledgement with committed event hash, operation results and rejected array. The executable Edge uploader uses a deterministic batch-derived idempotency key, strict response decoding and binds an ACK to the exact pending batch before atomically persisting cursor/hash with journal acknowledgement across restart. A shared deterministic golden vector proves Edge builder/Fiscal verifier compatibility.
- Accepted offline `FISCAL_SALE` commands are persisted by Fiscal and may be completed by a later sync batch after either side restarts. A terminal device result atomically materializes the tenant sale, operation, normalized receipt artifact and webhook/audit outbox event; malformed currency, totals, operator, tax, payment or tenant/device bindings fail closed. Same-batch acceptance/completion and split-batch correlation are idempotent.
- Signed Fiscal webhook outbox with retry/backoff and MiniPOS HMAC receiver; polling remains available as the authoritative fallback.
- Fiscal→MiniPOS/Edge webhook delivery now follows the canonical `t,kid,v1` signature over `timestamp.raw_body`, and both receivers enforce constant-time HMAC plus the 300-second replay window before JSON parsing. Delivery failures are isolated per endpoint, use the documented 10s/30s/2m/10m/1h/6h/24h schedule, and HTTP 410 durably disables a dynamic endpoint instead of retrying it.
- Dynamic tenant-scoped webhook endpoint create/get/update/disable/secret-rotation lifecycle is persistent and idempotent. Secrets are disclosed only once, GET is redacted, a 24-hour previous-secret overlap is recorded, URL/event validation fails closed, and the dispatcher selects active endpoints by tenant/event and signs with each endpoint secret. Per-endpoint delivery checkpoints prevent replaying already successful destinations when another destination retries; the egress client disables proxies/redirects and rejects private/loopback/link-local DNS answers at connect time.
- MiniPOS checkout validates malformed Fiscal responses without panic and persists tenant-scoped idempotency request hashes; a reused key with a different payload is rejected.
- Every public MiniPOS mutation now has a durable tenant/path/method scoped idempotency record with request hash, exact response replay, restart recovery and mismatch rejection.
- MiniPOS products/employees/shifts/orders now emit UUID/resource metadata, status/unit/roles, exact EUR totals and timestamps required by OpenAPI; line writes enforce optimistic `If-Match`, UUID, quantity/tax/money and same-tenant product ownership.
- Signed Fiscal events are first durably stored with their raw body in the autonomous MiniPOS webhook inbox, then applied by monotonic fiscal version; event replay and event-ID payload substitution are handled safely across restart.
- Offline Edge sale webhooks carry `external_id`; MiniPOS links them to the locally created order even before a cloud sale ID exists, persists the Fiscal sale/operation IDs and applies monotonic terminal state. This closes eventual reconciliation of a successful BLE checkout into the autonomous MiniPOS database.
- BLE session issue/refresh/revoke is durable, tenant-scoped, signed and exposes the canonical OpenAPI field names and GATT UUIDs.
- BLE Edge primitives now include canonical RFC 8949 deterministic CBOR, strict decoding, payload hashing, X25519/HKDF-SHA-256 key agreement, AES-256-GCM directional counters, exact binary GATT framing and MTU 185/247/517 chunk tests.
- BLE flow control now enforces one in-flight message, ACK state (`highest_contiguous`/missing bitmap), duplicate consistency, BUSY, cancel and resume; an integration test carries a canonical encrypted/chunked CBOR sale through reassembly into the durable Edge runtime and proves device exactly-once replay.
- Edge now implements the complete ticket-validated handshake state machine: HELLO binding/scope/expiry checks, X25519/HKDF-SHA-256, AES-256-GCM encrypted AUTH_PROOF, constant-time proof validation, READY and replay rejection, producing the directional encrypted transport session only after success.
- MiniPOS has an executable REST/BLE/BLOCK decision model with separate transport/device metrics and tests for cloud loss, final-device loss and session expiry. Chrome Web Bluetooth performs secure-context/user-gesture discovery and the matching HELLO→CHALLENGE→AUTH_PROOF→READY WebCrypto handshake; fiscal execution remains unavailable until READY. After READY it canonical-CBOR encodes commands, splits them for the negotiated ATT MTU and emits the exact encrypted BLE v1 binary frames with directional key derivation and monotonic counters. Incoming directional frames enforce tag/counter/header checks and are gap-aware reassembled with one-message BUSY and duplicate-consistency rules before reaching the UI; encrypted ACK/NACK progress is returned through the Flow characteristic.
- MiniPOS checkout transport now freezes the route before the first side effect: healthy cloud uses REST, unavailable cloud uses BLE only with a live final device and valid READY session, and final-device loss blocks the sale. An ambiguous REST result becomes `UNKNOWN/RECONCILE` and is never retried over BLE. Offline commands carry a bounded expiry and SHA-256 of canonical CBOR payload.
- BeeMiniPOS now has a native Android/iOS GATT client based on `react-native-ble-plx`: platform permission handling, service-filtered scan, connect/discovery, MTU negotiation, notifications, authenticated HELLO→CHALLENGE→AUTH_PROOF→READY, encrypted command chunks, ACK/NACK flow and correlated terminal result. Portable Noble cryptography removes WebCrypto/base64 browser dependencies while preserving the same X25519/HKDF/AES-GCM protocol on Web and native.
- Web BLE now offers a correlated send-and-wait primitive with bounded timeout, exact message/operation binding, duplicate suppression and waiter cleanup. The reusable fiscal checkout adapter maps both REST and BLE terminal results into the same COMPLETED/ACCEPTED/UNKNOWN/BLOCKED model. A short-lived encrypted `DEVICE_PROBE` traverses MiniPOS→Edge→final ФУ without allocating УНП/operation sequence; only its fresh READY result may authorize local fallback.
- BLE revoke is atomically persisted with a `ble.session.revoked` outbox event. Edge has a restart-durable SQLite revocation cache with expiry GC, and its handshake rejects cached revoked tickets before emitting CHALLENGE.
- Edge is now an executable, container-buildable process with guarded DEV/PROD configuration, graceful shutdown, periodic bounded sync draining, health endpoint and an HMAC-authenticated Fiscal control webhook. BLE revocation is acknowledged only after durable SQLite commit and survives process restart; invalid/tampered/non-revocation events fail closed.
- The Edge executable now composes authority, journal, runtime and a configured final-device adapter. A bearer-protected DEV/HIL transport executes canonical commands through the real durable path, enforces tenant/register/device/fencing binding, exposes the independent final-device probe, and is absent in PROD. Process restart smoke proves a completed command retains the same sequences/result with exactly two journal records and no second device execution. `simulator` hard-fails in PROD; unapproved tracks use an always-unreachable `unsupported` adapter.
- Edge has a transport-neutral GATT command processor that decrypts/reassembles frames, strictly validates CBOR envelope/hash/expiry, invokes the durable runtime and returns encrypted result frames correlated by message ID. Nested CBOR maps are normalized to string-keyed objects before driver JSON serialization; an encrypted end-to-end test covers the complete path and proves expired commands never execute.
- The GATT processor binds every command and probe to the authenticated ticket tenant/register/edge/fencing tuple before runtime invocation; cross-tenant or stale-fence commands never reach the device. BLE session `binding_version` exposes the actual fencing token through the existing OpenAPI field.
- Connectivity probes are durable and tenant-isolated; readiness/probe returns `BLOCK` when the final fiscal device is unavailable. Simulator unknown-after-send creates `UNKNOWN` and cannot be blindly retried.
- Core sale/operation JSON names, sale states, payment IDs and required action arrays are aligned with the canonical OpenAPI contract.
- Authenticated tenant-scoped Fiscal sales/operations and MiniPOS catalog/order filtering. Protected endpoints require the OpenAPI OAuth authorization scope `fiscal.base`. Public APIs enforce a centralized fail-closed RBAC policy: cashier sale/shift access, supervisor fiscal reports/reversal/export, administrator configuration/provisioning/webhooks, auditor read-only access and service-only Edge sync/diagnostics. Missing scopes and unknown roles are rejected.
- Production authentication now requires OIDC RS256/JWKS and rejects configured HMAC, missing issuer/audience/JWKS or non-HTTPS trust endpoints. Verification pins `alg=RS256`, selects a non-empty `kid`, validates issuer/audience/expiry/tenant/roles/scope, bounds JWKS downloads, caches keys and refreshes immediately for a rotated unknown `kid`; tests cover rotation, multiple audiences, wrong issuer/audience and attacker signatures. HS256 remains DEV/E2E-only.
- Production MiniPOS→Fiscal authentication now uses OAuth 2.0 client credentials over HTTPS instead of a static service token. The provider uses HTTP Basic client authentication, explicit scope/audience, validates Bearer token responses and bounded expiry, single-flights concurrent acquisition, caches with a 30-second safety window, invalidates on 401 and retries the same idempotent Fiscal request exactly once. Static `FISCAL_AUTH_TOKEN` is DEV-only and rejected in PROD.
- Both public APIs enforce an in-process tenant-keyed (authenticated) or source-IP-keyed (DEV) fixed-window limit, return HTTP 429 plus `Retry-After`, and leave health and the separately HMAC-authenticated internal webhook path outside that public-client budget.
- Typed Fiscal and MiniPOS schemas define LOGIN non-owner/no-`BYPASSRLS` roles, fail-closed transaction-local tenant context functions and `FORCE ROW LEVEL SECURITY` policies, including ownership-through-parent policies for line/event/order descendants. Each backend opens a physically separate non-owner reader pool; PROD rejects missing RLS credentials or reuse of the writer database user. Real PostgreSQL tests authenticate with those reader credentials and prove foreign-tenant invisibility and rejection of cross-tenant inserts.
- Fiscal sales/operations and MiniPOS products/employees/shifts/orders have authoritative typed hot-path projections with explicit tenant keys, EUR/money/version/uniqueness constraints, indexes and FORCE RLS. Projection upsert/delete is differential and occurs in the same serializable transaction as compatibility state; integration tests prove normalized values and that any typed constraint failure rolls back both representations. Tenant-bound typed mutations remain the next cutover.
- Persistent single-entity and collection hot-path reads for Fiscal sale/operation and MiniPOS product/employee/order (plus shift authorization) execute against typed tables through the separate reader identity in read-only transactions with transaction-local tenant/organization context. RLS returns no row for a foreign tenant; real PostgreSQL tests cover allowed and denied reads. DEV without persistent storage retains an explicit in-memory fallback. Mutation transactions still require cutover.
- Separate Fiscal and MiniPOS PostgreSQL migration baselines.
- Two isolated Compose projects with distinct PostgreSQL, private/ingress networks, Caddy ingress and explicit DEV/PROD overlays.
- Both backends tolerate transient Docker DNS/database readiness races with a bounded 30-second startup retry; permanent errors still terminate startup. DEV Caddy listens on `:80` so host and cross-compose routes work, while PROD remains bound to the explicitly required HTTPS site name.
- Touch MiniPOS and fiscal administration Expo UI for Android/iOS/Web. BeeFiscalApp now loads registered devices, filtered operations, persisted fiscal reports, effective country/tax policy and readiness/connectivity data from the public API; device and report rows are no longer hard-coded or locally simulated.
- Both Expo UIs now call backend APIs; MiniPOS no longer simulates a successful receipt and includes product, employee, location/workstation editors, active-employee selection, quantity controls and its commercial sales report.
- Kotlin stable driver interface and a buildable Daisy SMART S Android STUB app with deterministic fiscal/card/barcode/error scenarios, activated-terminal enforcement, debug-only plus PROD constructor guards and contract tests. Debug and unsigned release APKs compile; the release artifact cannot instantiate the STUB because `BuildConfig.DEBUG` is false.
- C++ protocol abstraction and exhaustive safe-fail command registries for Daisy and Datecs. Every one of the 88/73 documented IDs produces a disposition/retry/canonical classification; unknown IDs and conditional payment commands fail closed.
- Portable Daisy/Datecs frame encoders/parsers with BCC validation and compiled inventories of all 88 Daisy / 73 Datecs documented command codes.
- Edge measures allocated SQLite pages against `EDGE_STORAGE_QUOTA_BYTES`, exposes authenticated DEV/HIL storage telemetry, classifies 70/85/95/100% as WARNING/HIGH/CRITICAL/FULL and blocks a new fiscal command at 95% before probe, sequence allocation, journal append or device execution. Existing durable results remain replayable.
- A machine-checked release evidence generator inventories Go, npm and container dependencies as CycloneDX 1.6, hashes contracts/migrations/deployment baselines and emits a release manifest/checksum set. Until a release vulnerability report and cryptographic signatures exist, verification requires `UNSIGNED_NO_GO` and `PROD_NO_GO`; evidence generation cannot silently promote the build.
