# Actual installed-authority lifecycle prerequisite

Internal time authority now registers a noncopyable intrusive node owned by DeviceTimeAnchorCoordinator. Registration, removal and synchronous revocation all hold InstalledAuthorityGuard. The coordinator destructor takes the installed guard, unlinks its node and invalidates the referenced core before members are destroyed. The node also unregisters idempotently as the last member. Same-address coordinator reconstruction cannot adopt an old prepared exchange. It accepts only the coordinator's private typed invalidation function; no transport/user callback can register. Mutation lock order is installed guard → coordinator mutex → core mutex. Identity mutation takes installed guard before its private mutex; no core mutex crosses Identity signing/NVS work.

Actual production hooks are inside EncryptedProvisioning::install, ProvisionedBindingStore::install/open/close and DeviceIdentity::open/destruction. Valid input is checked before installation mutation begins. Beginning possible storage/key mutation increments a checked epoch and retires every registered core's pending/anchor before the first write. Same-byte binding close/open and identity object reopen/destruction therefore retire time authority, not merely different scope strings. Expected exchange captures the epoch; authenticated late completion compares it under the installed guard.

Failed write/commit/readback latches time-only quarantine for this process/boot. Successful later load/open/install or trusted_start_boot/trusted_binding_changed cannot clear it. Recovery requires a controlled reboot and the existing verified normal startup path; no time/epoch persisted cache is restored. No reset/mint/recovery API is added. Financial state is not rolled back or rewritten to hide uncertainty. Legacy binding and newly generated Identity scalar now read back committed data before success. An acknowledged durable commit followed by readback failure returns an error and leaves time unavailable; callers must preserve existing uncertainty semantics and reboot rather than treat it as an unperformed install.

Success only retires authority; it does not auto-start a core/provider. A trusted lifecycle owner must explicitly initialize a new boot-bound exchange after verified configuration. The production provider/route/relay remain absent/default unavailable. No live hot identity rotation API or mutable root trust API is introduced. NVS editing outside actual supported lifecycle APIs, secure storage anti-rollback, compiled trust image rollout and physical power-loss/entropy behavior remain separate acceptance items.

Actual host test modes (each separate process, so sticky state cannot be silently reset): encrypted success; legacy same-scope close/open pending ABA and active-anchor invalidation; encrypted write, commit and readback errors; legacy commit and readback errors; signed-invalid input preservation; real commit barrier versus root completion;1000 coordinator registration/destruction operations versus1000 actual legacy close/open operations; actual Identity reopen/destruction and same-identity ABA; actual new Identity key commit/readback failures; real cryptographically verified response paused before installed-lock admission while actual binding closes/reopens and trusted boot changes; same-address placement-new coordinator replacement; actual global Identity destruction at process exit.18 modes total, all required by mandatory native gate evidence markers.

The verifier pause exists only under BEEFISCAL_TIME_ANCHOR_CRYPTO_HOST_TEST, after actual canonical/root crypto verification. It grants no permit and is absent in production. NVS faults are host fixture-only. ASan+UBSan instruments actual coordinator/core/installer/identity and registry race; upstream static mbedTLS libraries are not sanitizer-instrumented. Objects referenced by a coordinator still must outlive it; registration cannot make arbitrary use-after-destruction calls valid.

Meaningful counterfactual RED: removing actual close mutation hook leaves an active core after close; removing sticky quarantine lets trusted_start_boot revive authority after failed write. Both fail native runtime assertions through actual Go/mbedTLS interoperability, not compilation. Removing coordinator destructor retirement also allows the same-address owner replacement to adopt an old valid response; bypassing scalar readback lets failed readback mark a new Identity ready. These additional counterfactuals likewise fail runtime assertions. Existing BLE proof interval40 cases, pure core5229 oracle/10050refresh/RED and actual startup entropy/DRBG tests remain required. No HIL, UTC health or legal acceptance claim.

The shared installed guard and registry use fixed aligned in-place storage with intentionally no destruction or heap allocation. This boot-lifetime policy also covers host/global Identity and binding destructors constructed before the first guard use. Epoch and mutation-depth counters do not wrap: exhaustion latches time quarantine. This is not a durable anti-rollback counter.
