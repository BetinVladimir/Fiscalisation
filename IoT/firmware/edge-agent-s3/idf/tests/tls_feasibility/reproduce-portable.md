# Reproduction scope

All sources are isolated feasibility fixtures, not production modules. Run only with freshly generated synthetic keys. No production credentials, device writes, financial operations or hardware access are used. Physical S3 identity keys stay inside ESP32-S3 NVS; ATECC608A/608 is not used.

Pin upstream mbedTLS tag `mbedtls-3.6.7`, commit `068ff080b369adfac81509f9b57b2afabaf82dc5`, including framework submodule `dde0c4a0e448a0552f18817dcea633bb851fd288`. This upstream portable client dependency does not replace the ESP-IDF vendor submodule. Clone into `mbedtls-3.6.7`, then `./reproduce-host.sh`. `gen.go` generates ephemeral ECDSA-P256 CA and ServerAuth SAN leaf plus expired/client-purpose negative fixtures; `make_assets.py` generates assets.h locally. Do not commit PEM files/assets.h.

Host results: C-to-C memory-BIO TLS1.3 with17/23/31-byte transport fragmentation; wrong-name and expired client rejection; ClientAuth-only leaf rejected by server certificate selection (this is not evidence of a client-side EKU adversarial test); independent Go TLS1.3 client validates CA/name/ServerAuth and echoes synthetic payload through C memory-BIO server.

Android: CMake `-DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-24`, ENABLE_TESTING/PROGRAMS OFF, build all three static libraries. Compile engine.c with aarch64-linux-android24-clang and link shared .so against those libraries. Tested NDK27.1.12297006. Hermes should call this native C ABI through JSI/native bridge; no Hermes-WASM assumption. JNI/Kotlin/JSI integration, keystore auth PoP and Android runtime execution remain OPEN.

iOS: CMake `-DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_ARCHITECTURES=arm64 -DCMAKE_OSX_DEPLOYMENT_TARGET=15.1 -DCMAKE_OSX_SYSROOT=iphoneos` (and separately simulator absolute SDK), build static libraries, compile engine.c with xcrun matching SDK/target and combine with libtool. Tested Xcode26.5 SDK. Compile/link only, no signed app or simulator/device execution; Swift/ObjC bridge and keychain auth PoP remain OPEN.

WASM: pinned emsdk4.0.20 commit `e4fe26ef59168ff44f4c23c466e497bf60b3411e`, install+activate locally. emcmake cmake mbedTLS with tests/programs OFF; build all three libraries. Link main.c with those libraries via emcc `-O2 -sASSERTIONS=2 -sSTACK_SIZE=262144 -sALLOW_MEMORY_GROWTH=1 -o c-fixture-wasm.js`. Original default64KiB stack overflow was detected; bounded fixture stack is explicit. Node runtime and actual Chromium page both PASS C-to-C TLS1.3; this does not test WebBluetooth or JS↔WASM API ownership/zeroization.

`browser.cjs` uses Playwright installed in the existing BeeFiscalApp dependency tree; set PLAYWRIGHT_MODULE to an alternate absolute playwright module path for another machine. Starts a localhost-only static server, loads index.html, waits for explicit PASS/abort, closes browser/server.

S3 SDK candidate: official ESP-IDF5.5.6 commit `880a203ae603d08a94d06aa01e0d6761958e5e9e`, vendor mbedTLS `2b96dd8eebe880f304c69976b3c2fa0c5100cbb6` (3.6.7); official supported Xtensa compiler `esp-14.2.0_20260121`; CMake3.31.10. ALL candidate caches, Python env and PLATFORMIO_CORE_DIR must be /tmp. Original global SDK remains PlatformIO3.50400.0/IDF5.4.0. Do not repeat local framework override with global PlatformIO core.

Legacy PlatformIO6.10 SCons fails duplicate esp_efuse_fields.c object basenames. Direct generated official CMake/Ninja build is used for bounded compile proof; this is not a proven production PlatformIO upgrade. `/tmp` symlink exposed an IDF toolchain comparison bug: apply idf-candidate-pathfix.patch only to isolated candidate; it canonicalizes CMAKE_TOOLCHAIN_FILE before taking dirname. No cryptographic vendor source patches or unsupported compiler-check bypasses are used. Full-app candidate manifest changes IDF bound only to ==5.5.6 in isolated copy. Production manifest is unchanged.

Future production wrapper must add full-SPKI expected binding/pin checks, strict epoch ownership, bounded reliable GATT adapter, async lifetime/disconnect zeroization, typed errors/deadlines, memory instrumentation, OS/browser-key challenge-PoP, validated root keyring/cert rotation and offline-time policy. engine.c is intentionally a small proof fixture; initialized contexts are released on initialization failure, but production ownership/pinning/authentication integration remains incomplete.

Negative tests require exact rejection stage/error/verify flags and fail if a prohibited handshake completes. `counterfactual.py` builds a separate mutated fixture with client verification disabled and hostname normalized; hostname/expiry tests must return15 and print forbidden-handshake failure. These mutation checks do not modify the tested engine source. `.gitignore` excludes generated PEM/assets/build artifacts.

## Integrated reproduction corrections

Host script checks exact upstream/framework git commits and clean tracked source before generating ephemeral assets. Cross script now configures and builds the iOS simulator libraries from a clean directory; Go interop kills its fixture server after ten seconds to bound a blocked handshake/read. Root reran host, Android/iOS cross-link and actual Chromium four-case WASM tests successfully. The historical S3 `/tmp` workaround above is not the preferred SDK migration path: a later pristine official full-app build with TLS1.3 enabled succeeded from a physical no-space isolated directory; see repository doc48 for current candidate evidence. No vendor pathfix is applied to production.

Generated WASM is a two-endpoint synthetic test and embeds its generated disposable server private key; never ship that fixture binary as a production client. The common engine source has no embedded keys and still lacks production pinning/auth/transport/lifetime integration. Keep all generated PEM/assets/binaries ignored.

## Independent server presents a forbidden EKU

`peer_server.go` is a Go TLS1.3 server using GetCertificate to force the generated ClientAuth-only leaf; it does not prefilter the server certificate by its own EKU selection. `peer_client.c` runs the actual common mbedTLS client and asserts client-side MBEDTLS_ERR_SSL_BAD_CERTIFICATE (-0x7a00) with exact EXT_KEY_USAGE verifyflags0x1000. The positive ServerAuth control must exchange a synthetic message. Both peers are disposable host fixtures, not firmware/native/browser production channels. The extended counterfactual disables client verification in an isolated engine copy and requires this independent-peer negative test to fail because the forbidden handshake completed. This adds client-side adversarial EKU evidence to the earlier server-selection negative; certificate enrollment/pinning/purpose issuance and device hardware gates remain separate.
