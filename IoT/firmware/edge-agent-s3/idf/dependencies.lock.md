# ESP-IDF dependency lock

- ESP-IDF: `v5.5.2`
- target: `esp32s3`
- `espressif/usb_host_cdc_acm`: `2.3.0`
- `espressif/usb_host_vcp`: `1.1.0`
- MQTT: ESP-IDF built-in `esp-mqtt`, pinned by ESP-IDF version
- BLE: ESP-IDF built-in NimBLE host, pinned by ESP-IDF version

`dependencies.lock` generated by the IDF Component Manager is committed after
the first successful resolved build. CI must use `idf.py reconfigure` with
component registry checksums and reject lock drift.
# ESP-IDF dependency baseline

- ESP-IDF: `5.4.0` (PlatformIO `espressif32@6.10.0`, framework package `3.50400.0`).
- `espressif/usb_host_cdc_acm`: `2.3.0`.

The VCP layer is provided by the managed CDC-ACM component's VCP API/example;
there is no separate `espressif/usb_host_vcp` registry dependency in this
baseline. `dependencies.lock` generated by the ESP-IDF Component Manager is the
machine-readable resolved dependency lock and must be committed.
