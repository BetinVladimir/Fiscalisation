# Exact int64 BLE result encoding

[Contract62](62_TYPED_CBOR_RESULT_ENCODER_CONTRACT.md) is implemented. The production result bridge parses original persisted JSON bytes with opt-in strict Unicode handling, promotes canonical lexical integer tokens to exact int64, preserves state aliases and uses the bounded typed encoder. It never passes wide amounts through double/cJSON. Integer heads use shortest1/2/4/8-byte representation and negative MIN arithmetic avoids overflow. Raw Value::Number, fractions/exponents/negative-zero tokens, duplicate keys, malformed Unicode/NUL and limit violations fail closed; output slots clear on failure. Existing generic Go-compatible JSON repair and global safe53 business policy remain unchanged.

The legacy cJSON compatibility wrapper accepts only finite integral safe53 values and checks its encoded budget before copying strings/children. It cannot recover a previously rounded token or bytes after a C-string NUL; those provenance guarantees belong to the production strict bytes bridge. No claim of restoring lost legacy information is made.
