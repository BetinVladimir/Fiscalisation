# S3 activation fiscal identity contract

S3 activation is explicitly typed by model `EDGE_AGENT_S3`. Its board serial identifies a factory-enrolled adapter, not the fiscal printer. Before invoking the credential issuer, the server requires exactly one factory key assignment to the claimed tenant and an existing separate ACTIVE FISCAL_DEVICE resource on the claimed register/location. Current physical profiles are Datecs DP-150 MX and Daisy Compact S 01. The physical resource must provide a valid eight-character fiscal device number and fiscal-memory number; the activation's FMIN must match it. Resource ACTIVE here is the existing backend acceptance state, not newly manufactured hardware/HIL evidence.

The server reserves through `ReserveFiscalUNPRange(tenant, physical_serial, physical_fm, count)`. It never substitutes adapter board serial or FMIN as an UNP prefix. Ambiguous or unsupported embedded profiles, including legacy BLUECASH_50 without vendor identity proof, fail with `FISCAL_IDENTITY_PROOF_REQUIRED` before certificate issuance. Legacy FM leases still require the allocator's external physical-fence contract. This does not complete legacy BlueCash activation.

Credential issuance persists the exact physical resource ID alongside derived authority. Activation commit rechecks physical route, tenant/location, serial/FM and state, factory assignment/key and request expiry under the repository lock. It persists the S3 public key/KID using the actual firmware DeviceIdentity formula and a BLE advertising identity within the runtime size limit. It preserves fiscal and payment routes. Only the signed composite installation proof may activate an adapter route.

Executable evidence: production domain/API tests, positive factory-enrolled S3 lifecycle with separate physical fiscal resource and seven pre-issuer negative cases (board-serial-only identity, foreign physical tenant, wrong FM, unsupported embedded profile, wrong factory key, wrong assignment and changed physical route). Test fixture records and keys are disposable unit fixtures, not real device acceptance.
