# Trusted time: minimal production vertical contract for review

Read-only investigation began at Fiscalisation HEAD2f02765, 2026-10-21; final inventory is HEAD39bb9fc. The only reviewed-source difference is an explicit nvs.h include in device_time_anchor.cpp; it does not alter this contract. This is a proposal, not enabled functionality or hardware acceptance. It extends docs57/60/63; contract60's exact17/22 fields and checked int64 supersede provisional limits in57. Device keys remain ESP32-S3 NVS; ATECC608 is unused. No original files changed.

## Decision needed before implementation

Approve one complete deployment profile: Linux root service with a locally supervised authenticated UTC synchronization source, a bounded-error AuthorityClock, purpose-specific root issuance, an opaque phone BLE bootstrap relay, actual installed-authority invalidation hooks, and S3 interval-provider integration. All new dependencies must be explicitly configured; absent clock/source/signer/feature policy means unavailable. Do not default-enable a route or replace unavailable time merely because foundations compile.

The remaining blocker is operational as well as code: no actual deployment supplies a reviewed UTC error/health guarantee. Choose an authenticated upstream time service with an accepted error SLA and a local daemon configuration/monitoring contract. Authentication alone does not establish an absolute error bound against all asymmetric delay or a faulty upstream. If that trust/SLA cannot be accepted, do not issue V1 healthy time. time.Now, OS synchronized=true, successful SNTP/NTP exchange, or an invented uncertainty constant are insufficient evidence.

## Server AuthorityClock: concrete bounded contract

New internal API `Sample(ctx) (AuthoritySample,error)` and `StillCurrent(ticket) bool`. Sample contains inclusive UTC lower_us/upper_us at local monotonic capture, boot identity, health epoch, policy revision, opaque current ticket and bounded valid-until-monotonic. All fields are checked int64; nonnegative ordered UTC bounds. No constructor accepts caller-declared healthy=true. Monotonic clock is process/host runtime, separate from wall clock. Restart, suspend, monotonic fault, upstream change, leap-policy change, unknown source, stale supervision, large offset/step, or lost synchronization invalidates health epoch. A later healthy recovery never resurrects prior tickets, including A→B→A identical source/time.

Recommended first deployable adapter: trusted same-host monitor queries an explicitly configured time daemon over a local root-owned Unix endpoint; verify peer credentials/filesystem ownership and configured source allowlist. It combines actual synchronization/source authentication status, upstream error SLA, root delay/dispersion/error metrics, sample age, bounded local oscillator holdover, collection duration and integer quantization. Also detect OS wallclock-vs-monotonic discontinuity with bracketing captures and kernel unsynchronized/error state. Reject missing/unparseable/version-unknown metrics, local-clock fallback, excessive offsets/errors, unauthorized upstream, stale/replayed boot/sequence reports and unsupported leap/smear state. Avoid shelling out to locale-dependent command output in request handlers. Pin/test the selected daemon protocol and deployment package version before implementation acceptance.

Monitor is an OS/deployment trust boundary, not an independent cryptographic proof of UTC. A Unix report cannot certify a compromised host. Optional remote signed attestation is a different profile, requiring trust and replay/age policy; do not silently treat it as this profile. Capture uncertainty conservatively using outward integer arithmetic; do not use half RTT or average clock offset as a guaranteed error bound. A sample maximum age and health error ceiling are explicit reviewed deployment policy, not hardcoded evidence of precision. Multi-replica servers each need their own healthy adapter; load-balancer time is irrelevant.

For response V1, choose a checked integer millisecond representative within the healthy interval; set uncertainty_ms to ceil(max distance to both inclusive endpoints), including capture/quantization uncertainty. It must fit device250ms policy; otherwise no signature. max_rtt_ms/max_holdover_ms are server caps no larger than firmware policy. Clock sample is obtained after PoP/authority validation, immediately before signing. Final admission compares original health ticket after signing; elapsed signing time is inside device measured RTT. Any change/loss invalidates response, including stale errors. No signed denial becomes a time anchor.

To achieve agreement with certificate issuance, replace that optional issuer's naked clock dependency with the same AuthorityClock and a bounded validity policy: challenge issued_at must not exceed device lower seconds at proof admission, expiry exclusive; certificate NotBefore/NotAfter validity must contain the accepted interval. Define seconds quantization explicitly and keep existing wire fields. A minimal deployment may expose time issuance only for integration tests while certificate route remains disabled; that is not completed Stage B acceptance. Execution/local tokens remain separately gated follow-ups.

## Root issuance and atomic authority ownership

Proposed new disabled-by-default route `POST /devices/{device_id}/trusted-time:anchor` accepts the exact4-key envelope only, max4096 bytes and strict body deadline. Authenticated actor requires an explicit registered-device setup/certificate-management permission and exact tenant/location/register association. Do not open anonymous activation challenge route as a signing oracle. Relay actor does not supply a key, time, nonce, binding lookup fallback or issuer PEM.

Service verifies exact request canonical17-field schema, canonical low-S P1363, P256 SPKI from enrolled active platform_device/current activation, actual device transaction key/kid and installed signed binding record. Compare requested device/path, scope/hash/generation/root ID to those records. Select current binding by authoritative exact association; no request-supplied arbitrary resource selection. Refuse legacy missing installation evidence. Preserve strict DER22-field response and the two fixed domains in60 unchanged.

Add private `verifiedDeviceTimeIssuancePermit` containing validated immutable request, request transcript digest, source versions/activation identity, actor/session permission epoch and health ticket. Only service creates it. Root signer `signDeviceTimeAnchor(permit)` cannot sign arbitrary JSON or be reached through generic hash methods. It validates purpose/root key policy and checks returned inner/outer signer ID equality. Initially reuse explicitly time-authorized compiled binding-root key; separate time key/catalog rotation is a later reviewed wire/trust profile.

Authority precheck then ordinary postcheck is insufficient if revocation can commit between postcheck and publication. Use the repository's actual atomic source-version confirmation model: final transaction/lock compares all source and actor permission versions plus readiness/recovery fence; either reserve an exact confirmed response result for publication or fail. Clock health epoch must remain current at that final linearization. No repository uncertainty fallback. Release DB locks before expensive cryptography; snapshot→sign→atomic compare-and-confirm. Health invalidation and publication share the clock owner admission primitive; no server callback can claim current ownership merely by reloading the latest ticket. Network delivery after a successful decision can still be delayed and is safely bounded by S3 RTT; revocation after publication is not retroactive deletion of a packet.

This read-only operation must not create orders, execution authorizations, receipts or install new binding. Audit only bounded request hash/device/authority policy/outcome; never private keys, JWTs, full financial journal or arbitrary relay payload. Enforce per-device+actor limits and a small in-flight bound; repeated identical PoP may receive an independently healthy response but cannot extend an already consumed S3 ticket. Do not add an unbounded server nonce ledger.

## S3 owner, entropy and provider

Create one `DeviceTimeRuntime` owned for app lifetime; it owns nonce DRBG, esp_timer monotonic adapter, core, coordinator, signer/verifier, relay slots and `TrustedBLECertificateTime` adapter. Startup seeds a dedicated mbedTLS CTR-DRBG with distinct personalization under existing with_startup_entropy before RF/ADC; no NVS restore. Never call raw esp_fill_random after radios stop assuming adequate entropy, and never toggle SAR under active RF. Nonce source returns only32-byte purpose nonce internally, zeros outputs on errors, enforces a bounded request budget/no automatic hardware reseed. Core rejects zero/recent repeats and sequence exhaustion; boot/request uniqueness rests on genuine startup entropy, not ring history alone. Budget exhaustion requires controlled reboot/reseed with all authority revoked; it must not silently wrap or indefinitely disable a normal workday. Stress budget jointly with signing demand and measured target resources.

Monotonic adapter checks esp_timer_get_time result, nonnegative checked range and lifecycle epoch. Drift1000ppm and30s/5s caps are current engineering limits, not verified oscillator accuracy. Production policy requires measured worst-case temperature/power/load/frequency behavior and margin. First profile disables sleep while authority exists; explicit before-suspend/deep-sleep/restart invalidates. Unexpected timer reset/backwards/unknown continuity quarantines; no wallclock fallback. SNTP/settimeofday changes do not affect it. Boot nonce generated once per true runtime boot; ordinary refresh never calls start_boot.

Provider reads core inclusive microseconds and converts each endpoint using checked floor(us/1e6); preserves inclusive bounds, validates positive/int64/order and clears outputs on failure. It must also bind the current lifecycle owner so an old anchor cannot survive an actual installer update. Lock order is installed-authority guard → coordinator/runtime ownership mutex → core; never take connection lock while acquiring those locks. Existing proof signer already holds installed guard, which is recursive; do not introduce reverse provider→installed order through callbacks. Both proof admission/publication remain mandatory, including cached proof and actual signing delay.

## Actual lifecycle hooks: close ABA at mutation boundaries

Introduce a single installed-authority lifecycle bus/epoch owned at startup, registered before consumers can publish and kept alive longer than stores. It exposes narrow trusted begin-mutation/confirmed-snapshot/fault operations, not a caller-set epoch. Stores call it under existing installed guard. Begin increments checked nonreused epoch, revokes anchor/pending/prepared relay/cached proof publication BEFORE the first persistent write or identity destruction. Failed NVS commit/readback/ambiguous state stays unavailable even if old bytes happen to match. On verified stable snapshot, coordinator gets fresh boot-bound state for that lifecycle generation; it may not retain old healthy anchor. Notifications are internal synchronous code without arbitrary external observer callbacks/reentrant user code.

Required actual entrypoints: encrypted install; legacy binding install/open/close; device identity reload/replacement/factory reset (currently no general rotation API, so introduce only an explicit guarded lifecycle transaction); firmware root-policy replacement/startup; suspend/restart. A valid rejected packet before mutation need not retire healthy anchor. For legacy same-byte reopen or installer uncertainty, err on revocation. With compiled immutable root, rotation is firmware restart/new image: no mutable relay root override or unsupported hot setter. Explicit signed key migration must enroll new key, install matching signed binding and reboot/reinitialize under a new epoch; old pending never adopts across rotation. NVS rollback does not become trusted secure monotonic storage: online server installation state rejects stale binding; offline secure anti-rollback is not claimed.

Identity operation must join installed guard before its own mutex on mutating paths; current open-only mutex cannot by itself linearize rotation against proof/signing. No core mutex across Identity signing. Lifecycle mutation uses installed→runtime→core revocation, then releases core before identity/NVS work; locks remain ordered. Publication rechecks immutable epoch even when exact scope/SPKI/root bytes return A→B→A. Callback must carry admitted owner; it cannot fetch latest owner after await and cancel it. Register/unregister lifetimes and lock ordering get dedicated deadlock tests.

## Opaque bootstrap/relay contract

BLE bootstrap only has START/READ_REQUEST/SUBMIT_RESPONSE/STATUS/CANCEL_OWN exchange actions. No generic sign/settime/execute/discard operation. Use a new purpose-framed endpoint or dedicated characteristic; do not overload provisioning-only control semantics or financial intent parser. Size≤4096 inner envelope with bounded fragments, single assembly per connection-generation+exchange token, max deadline and digest; cap total buffers and in-flight work. Fresh slot token/connection generation is not cryptographic authority but prevents old UI callbacks cancelling a new task.

START snapshots current installed lifecycle and calls signer.begin; returned prepared packet is not network publication. Immediately before each request publication/fragment send, runtime compares captured slot/ticket/lifecycle and connection owner; replacement can stale returned bytes, but can never cause response adoption. Public opaque exchange ID maps to private ExpectedTimeAnchorExchange only inside S3. Reconnect retires transport slot and its own pending ticket, not unrelated new slot/healthy anchor. A late SUBMIT carries old slot and stays inert. Parsing/signature work happens on bounded worker, not NimBLE callback under connection mutex. Receipt m1 remains after complete body/crypto verification. Invalid unsigned packet does not clear valid pending; flood limits may close only that connection.

Phone modules hold exact auth+device+register+connection+exchange owner across await. They transmit canonical_json as opaque text without numeric parsing/re-encoding; HTTPS uses ordinary validated phone TLS. Token/session/logout/config/device switch aborts only admitted relay task, empties transient response and blocks late UI publication. Never persist authoritative time, expected handle or server token with the journal. No requirement for S3 certificate validation or valid S3 wallclock before this path; no global TLS verification bypass. Device PoP+root signature+fresh nonce establish bootstrap authority, while actor auth prevents remote signing abuse. Delay/malicious relay results in unavailability, not guessed time. Direct MQTT/HTTP adapters are later optional transports using the same owner/ticket contract; first vertical need not implement every transport.

## Acceptance tests that distinguish integration from another foundation

- Actual Linux monitor adapter protocol fixture: healthy allowlisted authenticated source with real bounds; stale/replayed boot+seq, malformed metrics, unsynced/unknown upstream, unauthorized peer, step/leap/suspend, daemon restart, error/SLA ceiling breach all deny. Process/OS monotonic and wallclock jumps tested independently. A fake Sample used by domain tests is not monitor acceptance.
- Actual service/API + clean PostgreSQL/RLS: owner permits, wrong actor/tenant/register/key/binding/install evidence denied; canonical17/22 golden vectors through independent actual C++ verifier; no financial writes. Deterministic barriers revoke key/binding/activation/session or flip persistence readiness/health after precheck/during signing/before final confirmation. No response when ownership lost; A→B→A rejects original source epoch. Inject stale errors too.
- Root purpose constraints: wrong domain/profile/key/canonical integers rejected, no raw signing path; healthy lower/upper quantization at millisecond boundaries, uncertainty overflow and limits; health lost/recovered to identical values cannot republish old permit. Existing certificate validity paths use same health policy before claiming agreement.
- Actual production S3 adapters + REAL encrypted/legacy installer APIs: hold real signature/verification at explicit barriers; install new binding, failed commit/readback, close/reopen, actual identity replacement and boot/trust image-owner change. A→B→A retires old prepared request/anchor/cached BLE proof, old cleanup cannot retire new. Direct coordinator calls alone do not satisfy these tests. Simultaneous installers, bounds reads and callbacks must complete without deadlock under reviewed lock order.
- Actual nonce adapter startup ordering and failures: seed before first RF/ADC initialization; DRBG exhaustion/entropy error/repeated output stays unavailable; coldboot never restores NVS anchor;>10000refresh no nonce-history exhaustion; identity and nonce budgets measured separately. Actual target entropy qualification remains HIL/deployment evidence, not synthetic randomness tests.
- Real BLE bootstrap integration: maximum4096 fragmented request and response, wrong digest/offset/length/duplicate/interleaved frames, disconnect/reconnect handle reuse, stale START publication and late response, replacement after prepared return, body/verification beyond RTT, rate/memory bound. Use real app auth/session/config transitions against firmware ingress harness. No financial opcode can be reached. Missing marker/zero/SKIP tests fail mandatory gate.
- Provider+actual BLE certificate proof: coldboot unavailable, obtain root anchor over opaque relay, then real challenge proof succeeds; nbf/expiry straddle, time-provider loss/expiry during actual signing/cached-proof path returns empty. Fake wallclock/SNTP/NVS values cannot revive it. Replay cannot refresh holdover. Real source error/drift broadening crosses expiry and correctly denies.
- Actual S3 HIL: fresh erase/cold boot, RF startup entropy ordering, repeated power loss during install, temperature/power/frequency/load drift, disconnects and timed radio/body delays, controlled sleep/reboot, real phone Android/iOS. Record source/image/config hashes, oscillator/health policy and raw timing bounds; no private scalar/JWT logging. Successful host ten-phase crypto gate is prerequisite, not substitute.

## Release and scope

Do not mark this closed until a real healthy server source and actual runtime hooks/relay/provider are deployed in an isolated acceptance environment with the above evidence. Defaults remain unavailable through review. Immediate smallest next coding package should implement AuthorityClock interfaces and a selected real monitor adapter with deterministic protocol tests, plus actual installed-authority epoch hooks; those two independent prerequisites can proceed in parallel. Then bounded issuer/API, then S3 bootstrap/provider+phone relay vertical, then HIL enable decision. This avoids building a public healthy-time assertion before its health source exists.

## Root implementation decision, 2026-10-21

The next isolated implementation package is actual installed-authority lifecycle invalidation/epoch wiring. Use boot-sticky, time-only quarantine after an ambiguous persistent mutation or failed commit/readback; do not expose a same-process recovery/mint API. Preserve existing financial/installation behavior and document verified boot recovery. No production provider or route is enabled by this decision. Selection and operational acceptance of an authenticated upstream UTC source/error SLA remain OPEN.
