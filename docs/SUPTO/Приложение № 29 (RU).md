# Приложение № 29 к статье 52а Регламента № Н-18/2006 г.

> (Новое - ДВ, № 80 от 2018 г., изм. и доп. - ДВ, № 26 от 2019 г., вступает в силу с 29.03.2019 г., изм. и доп. - ДВ, № 75 от 2019 г., изм. и доп. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.)

## Требования к программному обеспечению для управления продажами в торговых объектах

1. Программное обеспечение поддерживает интерфейс на болгарском языке.

2. (изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Программное обеспечение обеспечивает полноту и целостность данных, создаваемых с его помощью.

3. В случаях, когда программное обеспечение для управления продажами в торговом объекте является модулем программного обеспечения, остальные модули не могут иметь дублирующую функциональность управления продажами или функциональность, направленную на обход требований данного приложения.

4. Программное обеспечение содержит встроенную при его разработке защиту от изменения или добавления без авторизации производителя/распространителя внешних модулей, позволяющих изменить функциональность программного обеспечения с целью обхода требований, указанных в настоящем приложении.

5. (доп. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Программное обеспечение использует по возможности надежный источник точного астрономического времени и обязательно обеспечивает синхронизацию времени между каждым рабочим местом и используемым им для печати фискальным устройством при запуске программного обеспечения или, по крайней мере, один раз в течение рабочего дня.

6. (изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Программное обеспечение имеет встроенные средства обязательного заполнения данных о пользователях (операторах): уникальный код пользователя (оператора) в рамках системы или торгового объекта, не менее двух имён, роль/права, начало/конец периода активности пользователя (оператора) для каждой из назначенных ему ролей/прав.

7. Программное обеспечение обеспечивает однозначную аутентификацию пользователей (операторов) при работе с ним.

8. (изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Программное обеспечение обеспечивает подключение к ФУ таким образом, чтобы позволять в реальном времени получать информацию о готовности ФУ к печати фискального чека и получать его ИН. Подключение проверяется:

- при запуске программного обеспечения с рабочего места, имеющего доступ к функциональности управления продажами - для проверки готовности ФУ к работе; при отсутствии ответа о подключении к ФУ или о готовности к печати фискального чека блокируется функциональность открытия продаж и оплаты, требующей выпуска фискального чека;

- при открытии продажи для целей генерации УНП; допускается для генерации УНП использовать ИН ФУ, с которым было установлено соединение в течение предыдущих 2 часов; по истечении этого срока блокируется функциональность открытия продаж;

- при оплате по продаже, для которой существует обязательство по выдаче фискального чека; в случае отсутствия соединения с ФУ или статуса устройства, который не позволяет выдачу фискального чека, программное обеспечение блокирует функциональность обработки платежей, для которых требуется выдача фискального чека.

Когда в торговом объекте более одного рабочего места, программное обеспечение блокирует функциональность открытия/оплаты продаж для конкретного рабочего места, для которого установлены указанные обстоятельства.

9. (доп. - ДВ, № 75 от 2019 г., изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) При вводе в программное обеспечение информации о продаже программное обеспечение генерирует уникальный номер продажи (УНП). Номер визуализируется как минимум в экранной форме по п. 9.1, за исключением случаев автоматизированного ввода (импорта) по п. 22, и формируется следующим образом:

Индивидуальный номер ФУ - Код оператора - Порядковый номер продажи.

Разделение элементов в уникальном номере продажи знаком "-" обязательно. Пример УНП: XXXХХХХХ-ZZZZ-0000001, где ХХХХХХXX - 8-значный индивидуальный номер ФУ, присвоенный производителем, ZZZZ - 4-значный код оператора, ввёл данные о продаже, согласно номенклатуре программного обеспечения, 0000001 - 7-значный порядковый номер продажи, формируемый отдельно для каждого индивидуального номера ФУ. Номер увеличивается по возрастанию с шагом 1 для каждой продажи и содержит только арабские цифры.

Когда в торговом объекте к одному фискальному устройству подключены два или более программных обеспечения для управления продажами, третья часть УНП - 7-значный номер, формируется в пределах заранее заданного диапазона для каждого из программных обеспечений. Диапазон должен исчерпываться по возрастанию с шагом 1, после заполнения его определяется новый диапазон.

9.1. (новое - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Для ввода информации о продаже в программное обеспечение считается момент ввода товара/услуги в экранную форму из пользовательского интерфейса или запись информации из экранной формы в БД.

9.2. (новое - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Когда обязанные лица осуществляют поставки с непрерывным/повторяющимся выполнением, УНП генерируется либо в момент заключения договора с клиентом, при условии что каждый платёж по договору отражается на этом УНП, либо в момент формирования обязательства за каждый период.

10. (доп. - ДВ, № 75 от 2019 г., изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) При вводе в программное обеспечение данных о способе оплаты по продаже, для которого согласно требованиям настоящего регламента должен быть выпущен ФЧ, программное обеспечение обязательно передаёт команду фискальному устройству на выдачу фискального чека, который должен содержать и уникальный номер продажи. Когда платежи по продаже более одного, уникальный номер продажи включается в выдаваемый ФЧ для каждого платежа, включая и Сторно-ФЧ, если таковой будет выдан.

При оплате по продаже, открытой до ввода в эксплуатацию программного обеспечения, для которой не был сгенерирован УНП, в фискальное устройство подаётся на печать УНП следующего вида: ОО000000-0000-0000000, где первые два символа - латинские заглавные буквы О, а остальные - нули.

11. Программное обеспечение не допускает печать служебных чеков для сделанных клиентских заказов в рамках одной продажи.

12. При аннулировании (полном или частичном) открытой, но незавершённой продажи программное обеспечение обязательно сохраняет в базе данных полную информацию об аннулированной продаже - аннулированные товары/услуги, количество, стоимость, оператор и др.

13. Программное обеспечение должно иметь надёжную защиту от преднамеренного или случайного удаления или изменения уже записанных данных о завершённых продажах:

- (доп. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) программное обеспечение не имеет встроенной функциональности удаления записей в базе данных, относящихся к информации по п. 15 и 18;

- программное обеспечение позволяет сторнирование завершённых продаж (сторно-операции), при этом обязательно сохраняет сторнированные данные.

14. (изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) При создании документов, отличных от фискального чека, программное обеспечение не обладает встроенной функциональностью генерации и печати документов, содержащих слова "Фискален", "Фискална", "Фискално", "Фискални" или производные словосочетания. Требование не относится к наименованиям торговцев, которые при печати сопровождаются их правовой организационной формой и их ЕИК, а также к виду закупаемого товара.

15. (доп. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) Программное обеспечение поддерживает информацию в структурированном виде, по крайней мере, для следующих выполненных действий:

- (изм. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) ввод/изменение пользователей (операторов) программного обеспечения, включая их присвоенные права или роль, в случае если права пользователей управляются присвоенной ролью - кто и когда выполнил действие и описание изменения;

- данные, связанные с действиями (операциями) пользователей (операторов) системы:

- имя пользователя (оператора);

- код пользователя (оператора);

- (зал. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.);

- дата и время действия (операции);

- вид действия (операции) - регистрируются как минимум следующие действия (операции): вход и выход в/из системы (login/logout), сторнирование, аннулирование и изменения в номенклатурах программного обеспечения; для действий (операций) "сторнирование" и "аннулирование" продажи - и уникальный номер продажи.

16. Программное обеспечение обеспечивает визуализацию через пользовательский интерфейс записанной по п. 15 информации с возможностью фильтрации по одному или нескольким критериям: период, пользователь (оператор), вид выполненных действий и др.

17. (доп. - ДВ, № 26 от 2019 г., вступает в силу с 29.03.2019 г.) Через пользовательский интерфейс программное обеспечение обеспечивает доступ к данным, создаваемым с его помощью, в сроки по чл. 38, ал. 1 от ДОПК. При архивировании базы данных программное обеспечение обеспечивает создание и поддержку архива, а также доступ к архивным данным в сроки по чл. 38, ал. 1 от ДОПК через пользовательский интерфейс. Не требуется доступ к архивным данным в случаях, когда создаваемая через программное обеспечение информация хранится в текущей базе данных в указанные сроки.

18. (доп. - ДВ, № 75 от 2019 г.) Программное обеспечение должно обеспечивать через пользовательский интерфейс визуализацию и экспорт данных из базы данных в табличном виде, в формате файлов XLS/XLSX или CSV, при применении следующих фильтров: Для торговца (при SaaS); Для периода (от даты до даты) и/или Для торгового объекта (все или конкретно указанный), и/или Для ФУ, на котором зарегистрированы продажи (все ФУ или конкретное ФУ), и/или Для рабочего места (все или конкретно указанное), и/или Для оператора (все или конкретно указанный). 19. Для целей контрольной деятельности НАП каждый софт должен иметь настроенный "аудиторский профиль" по аналогии с административным профилем, но с правами только для чтения. Аудиторский профиль должен предоставлять как минимум следующие возможности:

- доступ к функциональности программного обеспечения согласно п. 16, 17 и 18 (при SaaS - для соответствующего торговца);

- доступ к конфигурационным параметрам программного обеспечения (при SaaS - для соответствующего торговца);

- (доп. - ДВ, № 68 от 2020 г., вступает в силу с 31.07.2020 г.) полный доступ к справочной части программного обеспечения (при SaaS - для соответствующего торговца), за исключением справок, содержащих исключительно медицинскую информацию по смыслу чл. 27 Закона о здоровье.
