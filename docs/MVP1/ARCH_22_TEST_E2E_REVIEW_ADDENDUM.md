## 2. Новые e2e сценарии (формат ARCH_15 §1; профиль `e2e-local` + эмуляторы ARCH_20)

Золотой чек (общий оракул, `fixtures/rounding_golden.json`): строка 1 `unit 1234¢ × 1.000 − скидка 34¢ = 1200¢`; строка 2 `333¢ × 0.500 → (333×500+500)÷1000 = 167¢`; итог **1367¢**; оплата CASH **500¢** + CARD **867¢**. НДС (обе строки группа B 20%, ARCH_15 §0, ASSUMPTION(D-4)): `net=(1367×100+60)÷120=1139¢`, `vat=228¢`. Сумма карты в протоколе Datecs: 867 = `00 00 03 63` (тег 0x81); в JSON Smart: `5.00` и `8.67`, строго из целых центов (D-18).

### TST-E2E-21 · POS нативный BLE (путь pos.ble → S3/BlueCash)
- **Given:** POS-app с модулем POS-BLE-01…03, эмулятор `FakePeripheral` (E-6) с MTU 23 и 247, золотой чек; ключ `K21`.
- **When:** финализация по BLE; сценарии: (a) штатно; (b) потерян один фрагмент ответа; (c) разрыв BLE после записи команды, до уведомления.
- **Then:** (a) `FISCALIZED`, эмулятор ФУ получил ровно 1 документ на 1367¢ с платежами 500/867; для MTU 23 и 247 ответ собран байт в байт; (b)(c) результат `UNKNOWN`, **вторая запись команды = 0**, затем опрос статуса по тому же ключу даёт либо `FISCALIZED` с реальным номером, либо `NOT_FISCALIZED`; карта не возвращена до подтверждения.
- **Авто:** `make e2e-local E2E=21`; последняя строка `E2E TST-E2E-21 OK`.

### TST-E2E-22 · Smart S: HTTP localhost + Payment Bridge
- **Given:** `FakeSmartFiscalServer` + `FakeBridge` (E-3); золотой чек; PROD-профиль и LAB-профиль.
- **When:** (a) штатно; (b) ответ `payment_request` потерян; (c) ответ `PrintFiscalReceipt` `{ok,seq}` потерян; (d) успешный ответ `{ok:true,seq:n}` без номера документа.
- **Then:** (a) мост получил `payment_request` на **8.67**, фискальный запрос содержит платежи **5.00** (payTypeCode 0) и **8.67**; (b) `UNKNOWN` → `check_status` по тому же `reference_id` → `SUCCESS` → фискализация продолжается, повторных `payment_request` = 0; `NOT_FOUND` → карта не списана, чек не печатается; (c) `UNKNOWN`, повторный `PrintFiscalReceipt` = 0; (d) PROD: результат остаётся `UNKNOWN` (нет номера, F-1/F-2); LAB: `COMMITTED_NO_REFERENCE` с меткой LAB в чеке-журнале.
- **Негатив:** `PrintFiscalReceipt` содержит число не из целых центов (например 8.670000001) → тест падает (D-18).
- **Авто:** `make e2e-local E2E=22`.

### TST-E2E-23 · BluePay: прокси банковского сокета и восстановление
- **Given:** `FakeBluePad` + `FakeBankHost` (E-4), золотой чек, S3-профиль P-C.
- **When:** (a) штатно; (b) BLE рвётся после `0F/03 SEND DATA`; (c) потеряно `TRANSACTION COMPLETE (0E/01)`.
- **Then:** (a) сумма в команде покупки 867¢ (`81 04 00 00 03 63`), события 0F/01, 0F/03, 40/01, 40/02, 0F/02 в порядке спецификации, затем `0E/01` с `DF05` успех; (b)(c) `UNKNOWN`, повторной команды покупки **0**; восстановление: статус `0x1A`, затем запрос по STAN `0x24` (если STAN известен) либо отказ «STAN неизвестен» → ручное подтверждение (Q-B2 открыт); карта не возвращается автоматически.
- **Авто:** `make e2e-local E2E=23`.

### TST-E2E-24 · Рестарт и атомарность (D-3, TG-001)
- **Given:** backend на Postgres, 20 финализаций одним ключом параллельно; S3-эмулятор с `FAIL_AT` на каждой границе записи (operation, receipt, payment, outbox).
- **When:** убить backend между `PutOperation` и ответом; отдельно — питание S3 на каждой границе.
- **Then:** после рестарта ровно **1** документ на ключ; терминальное состояние и событие outbox либо оба есть, либо ни одного (проверка SQL-запросом по `operations` и `outbox`); CAS-конфликт возвращает `409` без потери данных.
- **Авто:** `make e2e-local E2E=24`.

### TST-E2E-25 · Оракул слотов оплаты по профилям
- **Given:** профили BC-50, Daisy Compact, Smart S; золотой чек; слоты читаются **только** из `fixtures/payment_slots_*.json` (BC-50 и Smart есть; для Daisy Compact файл создаёт задача из PDF 93PC).
- **Then:** для каждого профиля платежи на ФУ = CASH 500¢ и CARD 867¢ в слотах из фикстуры, Σ = 1367¢; для Smart S пока открыт Q-S8 карта в PROD отклоняется `BLOCKED_SPEC`, в LAB слот берётся из фикстуры.
- **Авто:** `make e2e-local E2E=25`.

### TST-E2E-26 · Порядок «сторно → возврат карты» на всех путях (D-12)
- **Given:** проведён золотой чек (CASH 500 + CARD 867) на каждом из шести путей.
- **When:** полное сторно.
- **Then:** в журнале вызовов фейков индекс «фискальное сторно подтверждено» **<** индекса «возврат карты 867¢»; при `UNKNOWN` сторно возврат карты не вызывается; на путях без команды возврата (Smart S, Q-P4) создаётся запись `REFUND_MANUAL_REQUIRED` и возврат карты = 0.
- **Авто:** `make e2e-local E2E=26`.

## 3. Правила исполнения тестов и e2e (дополнение к ARCH_15 §0)
1. Каждый e2e запускается трижды подряд; зачёт только 3 из 3 (иначе дефект тестовой среды → задача `BUG`, не «перезапустить»).
2. Фейк, вызванный сверх ожидаемого числа раз, ломает тест (счётчики вызовов обязательны во всех сценариях 21…26).
3. Тест не читает «ожидаемое» из тестируемого кода: числа берутся из фикстур или из золотого чека этого файла.
4. Любой сценарий с UNKNOWN обязан утверждать три вещи: нет повторной записи, нет возврата карты, итог разрешается чтением состояния.
5. Негативные векторы (`negative:true` в фикстурах) должны **отвергаться** парсером; тест, где такой вектор принят, — красный.

## 4. Карточки новых задач (подзадачи в `execution/status.json`)

### SEQ-01 · SEQ Datecs 0x20…0x7F на S3
Файл `IoT/firmware/edge-agent-s3/idf/main/serial_exchange.cpp` строка 23: `next_sequence_=sequence==0xff?0x20:…` одинаково для Datecs и Daisy. Для Datecs wrap на 0x7F, для Daisy на 0xFF (примеры вендора доходят до 0xDE и 0xC0). Сначала тест в `IoT/firmware/edge-agent-s3/idf/tests/serial_exchange_native.cpp` (96+ команд подряд: все SEQ Datecs в диапазоне, после 0x7F идёт 0x20), затем минимальная правка.

### TST-E2E-21 … TST-E2E-26 · см. §2

### TST-DEEP-13 · Daisy кодек против 17 золотых кадров
`DaisyCodec` из `IoT/protocol-abstraction/src/FrameCodec.cpp` кодирует и декодирует все положительные кадры `fixtures/daisy_golden_frames.json` побайтно, включая SEQ 0xC0 и 0xDE; негативный вектор «PDF typo» (SEQ 0x59, BCC не сходится) отвергается.

### TST-DEEP-14 · Золотые кадры DatecsPay и Smart
72 кадра `fixtures/datecspay_golden_frames.json` проходят разбор/сборку библиотекой `IoT/common-modules/datecspay`; `fixtures/smart_protocol_examples.json` валидируется строгой схемой (ключи без пробелов, `seq` не `sec`, суммы из целых центов).

### TST-GATE-01 · Запрет COMMITTED_NO_REFERENCE в PROD для Smart S
Тест конфигурации: профиль PROD + Smart S + ответ без номера документа → `UNKNOWN`; профиль LAB → `COMMITTED_NO_REFERENCE` с явной меткой; смена профиля LAB→PROD без перезапуска невозможна.

### TST-META-01 · Проверка матрицы тестов
`python3 docs/MVP1/tools/check-test-matrix.py` (создан): каждый `TST-E2E-NN` в статусе имеет карточку с `Then` в ARCH_15 или ARCH_22, у каждой задачи `TST-*` есть карточка, золотые фикстуры на месте и не пусты.
