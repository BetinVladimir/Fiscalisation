Для документной работы валидирует структуру и требуемые поля, не только наличие файла. Не использовать always-true, mocked production function, skip, чтение ожидаемого из реализации. Старую команду legacy_accept сверить с реальной структурой и запускать из harness только если она содержательно проверяет эту подзадачу. Scope точный: путь файла разрешает только этот файл; путь каталога — его потомков. Новый файл допустим только внутри явно указанного каталога, не рядом с разрешённым файлом. Если нужного пути нет в files — BLOCKED_SCOPE, не создавать его. Обязательны реально выполненные unittest assertions; skip/expectedFailure/no tests и assertEqual(константа,константа) не принимаются. Для кода запустить реальный native runtime/tests subprocess либо импортировать production Python module. Автостатус только TESTED_REVIEW_REQUIRED; независимое ревью проверяет смысл oracle и фактическое покрытие. Тесты не меняют source tree: временные БД/fixtures в tempfile, отчёты/raw evidence в os.environ["MVP1_ARTIFACT_DIR"] (отдельный каталог каждого из трёх прогонов); не писать generated evidence в git checkout. Для test-only работы разрешена временная мутация scoped production файла: контроллер восстановит его исходные байты перед green. Native subprocess обязан захватывать stdout/stderr и выдавать реальные ненулевые test counts (Go JSON, JUnit XML, unittest, pytest, TAP, GTest/Jest/CTest); python --version/echo/import без вызова продукта не являются runtime evidence.
